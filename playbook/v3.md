# quant-desk playbook v3

> **现行版本**（2026-11-13 起）。`quant_playbook` 返回的就是这份；
> 与提示词冲突时以它为准，与历史版本冲突时以它为准。

> 这是**规则**，不是预测。每条都来自回测或已验证的数据事实；改动必须走版本化。

## 0. 账户事实

- 本金 ¥5,000，只做 A 股模拟盘，不接真实资金。
- 100 股整手、T+1、单笔最低佣金 ¥5。
- **往返成本按金额分档**（佣金万 2.5 / 最低 5 元 / 印花税 5bps / 过户 0.1bps / 双边滑点 20bps）：500 元 → 225bps、1,000 → 125、1,500 → 92、2,500 → 65。
- **仓位越小越贵**：500 元一笔要比 2,500 元一笔多赚 1.6pp 才打平，「一手试仓」不是低风险，是高成本。
- 判据不写死数字：一律读 `quant_analog` 的 `net.by_horizon.*` 与 `cost_bps_roundtrip`。旧版 0.55% 对应约 3,300 元仓位，超过单票上限，已删。
- 最多 3 只；单笔风险 ≤ 4% 权益；现金 ≥ 20%。
- **可交易性是第 0 号门槛**：`quant_persona.current.tradable=false` 时，本账户当日没有任何买入路径，此时所有赔率判断都是空转。它不是「今天不适合交易」，是故障，必须修（见 §7），不许写成空仓结论。

## 1. 核心仓（已关闭）

CORE 于 2026-11-01 关闭：一手 511010 = 14,112 元 = 本账户 2.8 倍，防守日只能写 100% 现金净值行，那是买不起，不是空仓。原「25%–30%、2 只、-5% 止损」作废，章节号保留以免重编号。

## 2. 游资仓（AGGRESSIVE）

**数据结论先行**：2023–2026 年“涨停次日开盘买入 → 收盘”的日内期望全为负（首板 -0.14%、2 板 -0.30%）；以涨停价买炸板，次日开盘平均 -4.5%。**所以默认不做，只有满足全部条件才做。**

- 情绪：`quant_pools` 的 `tone` 为主升/修复，炸板率 < 35%，最高板 ≥ 3。
- 标的：当日板块龙头（首封时间早、封单额大、连板高度最高），**不是**跟风票。
- 入场：只在**分歧回封**或**龙头首阴低吸**时提票；不追一致加速板。
- 仓位：单只 ≤ `risk.limits.max_aggressive_single`（当前 50% = 2,500 元），同一时间只持 1 只游资票。v2 曾同时写 30%（本节）与 50%（`risk.limits`），只有后者有代码执行，前者让可买池凭空缩小约 40%。
- 退出：次日竞价不及预期（低开 > 2%）直接走；不隔夜死扛；-5% 硬止损。
- 禁止：一字板排队（买不到）、炸板接刀、连亏两笔后继续加仓。

## 3. 什么情况下空仓

- 数据 `core_usable=false`、`aggressive_usable=false`（做游资时）、`kill_switch=true`。前两项是**数据可用性**，不是准入。
- 当日亏损 -6%（不开新仓）、-10%（只减仓）。
- 账户回撤 -8%（仓位减半）、-12%（停止开新仓）。
- 没有能在 3 句话内说清“为什么是现在”的标的。

**空仓不是失败，是仓位。** 但空仓必须是一个判断，不能是一个制度故障：若空仓的唯一原因是 `tradable=false` / 袖已 `retired`，那不是空仓，是 §7 要修的故障。

## 4. 提案质量 checklist

提票前逐条自问：

1. 证据是什么？至少一个 `snapshot_id` 或具体字段，不是“感觉”。
2. 失效条件是什么？价格/时间/数据三者至少一个可验证。
3. 这笔的赔率是多少？目标涨幅 / 止损距离 ≥ 2。
4. 如果明天低开 3%，我还持有吗？
5. 这是计划内的 setup，还是错过之后的补偿性交易？

五条有一条答不上来，不提票。

## 5. 复盘（每个交易日）

- 计划 vs 实际：入场理由是否仍然成立？
- 偏差归因：数据错、执行错、还是情绪错？
- 只改一条规则，写进 journal，下一日验证。
- 每周统计：胜率、盈亏比、平均持仓天数、最大回撤、违规次数。

## 7. 窗口与权限

**7.1 人格判据的优先级（09:05）**

判定当日由谁花钱时，`current.tradable` 是**第一个**读的字段，且是一票否决：

1. `tradable=false` → 当日必须切换。`suited_to_regime=true`、`ready=true`、`missing_requirements=[]` 都**不能**救它——前三个描述的是「这条风格对不对今天的市」，`tradable` 描述的是「这个账户能不能下单」，两件事。
2. `tradable=true` → 才轮到比较 `suited_to_regime` 与 `eligible` 列表，决定保持还是切换。
3. 切换目标取 `today.candidates[0]`；`candidates` 为空才是真正的「今天不能交易」，此时写清是数据缺还是袖全关。

切换必须带 `reason` / `evidence` / `expected_edge_bps` / `invalidation` / `regime`——没有预期的切换事后无法结算。

**7.2 09:26 的兜底权**

原规则「换人格一律不许，只归 09:05」是绝对的，因此 09:05 一旦误判，全天无补救。改为：

- 09:26 读 `quant_persona.current.tradable`；若为 false 且 `today.candidates` 非空 → **09:26 必须切一次**，占用日限 2 次中的 1 次，并在 `open(D)` 第一行写「09:05 未切，09:26 兜底切换」。
- 其余情况 09:26 仍不得改人格。
- 13:35 / 14:30 / 19:30 一律不改人格。

**7.3 三个不能越权的动作**

- 任何窗口都不对账外账户 `propose`（账外只读，破线只写提醒）。
- 19:30 不重做结构复盘，只核数、只结账、只给明日三条与一条改动。
- 09:26 与 14:30 的「买不到 / 已剔除」只认盘中来源报价：`source ∈ {ths, eastmoney, tencent}` 且 `age_seconds` 不超过 `quant_market_status.fill.max_quote_age_seconds`（2026-11-09 实测 90 秒，与成交闸门同源；原写死 300，会放行内核必拒的报价）；`source=daily` 或 `age_seconds=null` 时不得以封板状态剔除，成交性交给 `fillability`。

**7.4 报告里的持仓数字必须现调（2026-11-05 加）**

任何报告（open / noon / close / review）凡涉及账外持仓的股数、成本、止损位，**必须现调 `quant_stops(account="external")`**，不得引用上一窗口的读数。2026-11-05 的 14:42 收盘报告引用了 13:36 的 100 股／成本 15.1502／止损 14.3927，而 13:49 已加仓至 200 股／15.1002／14.3452，止损位差 0.0475 元，而 14.49 正是当日技术失效位——足以让「减半还是清仓」判反。账外是真钱，这条没有例外。

**7.5 「买不到」只描述报价那一刻（2026-11-06 加）**

`limit_state=one_word` 只在**取价那一刻**成立，不是全天属性。2026-11-06 09:39 的 002529 海源复材是 `one_word`（7.39、ask 空），10:48 炸板，最低 6.45（距涨停价 −12.7%）、收 6.60，全天下跌 −1.79%——报告写成「买不到」，收盘即被否证。改为：报告写「此刻买不到（as_of=HH:MM）」，并在 13:35 / 14:30 各复核一次 `limit_state`；收盘仍 `opened` 的进「缺口」并计入次日对账。

**7.6 验收口径：测状态，不测成交（2026-11-09 加）**

7.1/7.2 的作废条件原写「切到 `trader` 后 3 个交易日内 0 笔 `propose` 通过 → 该改动作废，回退为『人格不切、如实记 0 笔』」。11-09 到期结算，结果与结论如下：

- 窗口（11-05／11-06／11-09）内 `propose` **0 笔尝试**，不是「被门拒」——`decisions` 最后一条是 11-02，`proposal_requests=0`。三天的「不买」是模型自己判的，没有一笔走到内核。
- 同期 `current.key=trader`、`since=20261105`、`tradable=true`、`open_sleeves=[AGGRESSIVE]`、`switches_today=1`：`CORE_RETIRED` 死路已解除，规则想达到的**状态**（账户有可执行路径）达成了。

**判据失效的原因**：它测产出，而规则的作用是状态。一个能被「不作为」满足的条件不构成检验——0 笔 propose 既可能来自规则无效，也可能来自没有机会，两者在这个数上无法区分。

订正为：

1. **规则保留**，7.1/7.2 不动。
2. 验收判据改为状态判据：`tradable=false` 且当日 `switches_today` 未增加的交易日，**连续 3 个** → 规则失效，作废。
3. 「0 笔 propose」单独记账，归赔率门（§8.5、§9.3），**不得**拿来给本条规则的存废作证。

这不是放宽。原判据把「不交易」当失败，订正后的判据把「死路未被修复」当失败——后者才是 11-04 立这条规则的唯一原因（账户有 5,007.51 现金、`open_slots=3`、`can_place_orders=true`，而可执行路径为 0）。

## 8. 跳空门按幅度分档

**8.1 判据（09:26，开盘价落库后）**

`x = 开盘价 / 昨收 − 1`，按幅度分四档：

| 档位 | 处置 | 理由 |
|---|---|---|
| `x ≤ −2%` | **一票否决**，不进赔率门 | 隔夜利空已定价，不是情绪 |
| `−2% < x ≤ 0` | **放行到赔率门**，否决理由只能来自 `excess_ci95` 跨 0 或 `analog` 无样本 | 小幅低开是情绪，不是利空 |
| `0 < x ≤ 3%` | 不变，进赔率门 | — |
| `x > 3%` | 维持否决，但必须记「若买」基准价 | 3% 上限按 §8.3 继续累计，到 n=10 再判 |

**8.2 放行路的限额**

`−2%~0` 档每日最多 1 只，仓位按 §2 的 `max_aggressive_single` 取整手，**没有单独的 10%**。5,000 × 10% = 500 元 < 任何一手，且 500 元往返 225bps，比 §0 任何门槛都高——那条限额不是风控，是让这条路必然走不通（11-10 的 002343 因此被挡，它当天封涨停）。

**8.3 3% 上限的验收（不改参数，只累计）**

2026-11-04 立：n=10 再判，若「若买」超额为正 ≥ 6/10 → 上限放宽至 5%。累计进度：

- 11-04：000530（正）、600715（负）→ n=2
- 11-05：002343（+7.72pp）、300006（+5.15pp）→ n=4，正 3 负 1
- 11-06：无 `x > 3%` 的票 → **n 仍 4**

在 n 到 10 之前，**不得**以单日结果改参数。这条本身就是纪律：拿两天样本推翻昨天定的判据，比不改更糟。

**8.4 作废条件**

连续 3 个交易日，`−2%~0` 档放行的票**平均超额 ≤ −2pp** → 回退为「`x < 0` 一票否决」。验收看 `declined` 的 `mean_excess` 与 `excess_ci95`，不看单日涨跌。

**8.5 这条改动的边界**

它**不**放宽任何仓位、成本、止损限制，只把「否决权」从跳空门交回赔率门。若放行后仍 0 笔成交，说明瓶颈在赔率门的 5 日超额判据（普涨日系统性给不出正超额），下一个改动的对象是它，不是跳空门。

**8.6 首日样本（2026-11-06）**

- `x ≤ −2%` 组 15 只：**11 对 4 错，组内平均超额 −1.43pp**。误杀 4 只：002696 +3.05pp、002181 +3.58pp、300182 +1.36pp、600825 +0.79pp。方向仍成立，**不改参数**（n=15、1 个交易日）。
- `−2%~0` 档 5 只：0 笔成交（5 只全部被赔率门否），平均超额 **−1.15pp**，未达 §8.4 的 −2pp 作废线 → **第 1/3 天**。

## 9. 档位不许用 T-1 的读数给 T-0 定档

**9.1 两个读数必须分开取**

- **阈值**（哪一档的边界）取自 T-1 收盘：`limit_up` / `break_rate` / `max_boards`，报告里注明 `thresholds_from=T-1`。
- **档位**（今天落在哪一档）只允许用**同一 `as_of` 的当日三值**，且必须 `pools.sentiment.phase != "opening_window"` 且 `gates` 三项非 null。`gates.* == null` → `tier = "undetermined"`。

**9.2 09:26 一律不输出档位结论**

当日 `limit_up` 在盘中是**下限**不是终值：2026-11-06 09:39 读 11、13:35 读 30、收盘 33；2026-11-02 09:41 读 1 只跌停、收盘 86。因此 09:26 只许写 `tier=undetermined`，**禁止**写「分歧 / 延续 / 退潮」。档位判定移到 **14:30 之后**，用当日 `limit_structure` 的 `counts.limit_up` / `seal_rate` / `max_streak`；结果只用于 14:30 的开仓与次日基准，**不回头改写 09:26 的结论**。

**9.3 09:26 的开仓许可：两条硬门，都要满足**

① §8 跳空门通过（`x > −2%` 且 `x ≤ 3%`）。
② 赔率门通过，两条同时成立：**经济门槛** `net.by_horizon.5d > 0`（扣本账户当笔往返成本后仍为正）；**证据门槛** `horizons.5d.t_stat ≥ 2.0` 或 `match.distance_band != far`。

过门即进仓位计算（§2 的 50%、整手、每日最多 1 只），不得在门后追加否决（§9.6）。

**为什么改（2026-11-13）**：旧判据要求 95% 区间**下界**高于成本，区间中位宽 1.80pp ⇒ 需点估计 > 1.81pp，而当日全市场最高 1.51pp，76 只 0 通过；另一支 `band != far` 又不要求超额为正（76 只放行 40 只、多数期望为负）。一支恒假、一支无经济含义，模型只好在门后自行加否决。

**9.4 补偿（2026-11-13 作废）**

10% 是「失去档位过滤」的补偿，但 500 元 < 一手，实测 0 次成交，随 §8.2 取消。

**9.5 作废条件（已结案）**

11-09..11-11 三日 0 笔，按原文「瓶颈在赔率门」结案；§9.3 已于 v3 重写。

**9.6 过门即过门（2026-11-13 加）**

§9.3 通过之后，不得再用「5 日净超额为负 / 绝对收益均值为负 / §0 目标收益 / §4 赔率≥2」否决该票——这四项是仓位与目标的语言，不是门的组成部分。11-10 的 002354 / 300432 / 300315 就是这样被否掉的（当天三只等权 open→close +3.11%、对市场 +1.34pp）。过门后：① 定尺寸（1 手起、≤ `max_aggressive_single`）；② 定失效（价格 / 时间 / 数据至少一个可被他人核对）；③ 走 `propose` → `ticket` → `approve`。一只都不提案时，报告逐只写否决项名称。
