# 草案：§8.2 增补「放行路·市场状态闸」

> 本草案需人工激活才生效。未激活前，首窗仍按现行 v3 执行（放行路每日最多 1 只、仓位按 max_aggressive_single 取整手）。

## 修改对象
v3 §8.2 放行路的限额。现行原文：

> `−2%~0` 档每日最多 1 只，仓位按 §2 的 `max_aggressive_single` 取整手，没有单独的 10%。

## 改后条文（替换 §8.2 全文）

**8.2 放行路的限额与启用条件**

`−2% < x ≤ 0` 档每日最多 1 只，仓位按 §2 的 `max_aggressive_single` 取整手，没有单独的 10%。

**8.2.1 市场状态闸（新增）**

09:26 读 T-1 收盘的两个字段：

- `quant_context.market.label == "stressed"`
- `quant_context.market.breadth < 0.35`

两者**同时成立**时，当日放行路**不启用**（上限 0 只），该档所有票一律否决，否决项名称写「放行路·市场状态闸」，不得改写成「赔率不够」或「买不到」。任一不成立则按 §8.2 原上限执行。

**阈值来源**：0.35 与 `stressed` 都不是新拍的数——内核 `market.label_basis` 自己写着 `risk_on≥50% / risk_off<35%`、`stressed≥0.75`，本条只是把这两个已有定义接成一条启用条件。字段在盘前就有值（T-1 收盘口径），不需要盘中数据。

## 为什么改（2026-11-13）

v3 取消 10% 额度是对的（500 元 < 任何一手，算术上必然 0 成交），但它只拆掉了**尺寸**障碍，没拆掉**时机**障碍：

- 当日 6 只放行票一手 632 / 751 / 1,030 / 1,122 / 1,250 / 1,261 元，全部 ≤ 2,500 元 → v3 下 6 只全部可执行。
- 结果 6/6 绝对下跌：600261 −9.34%（收于跌停）、603330 −6.02%、002249 −5.06%、600732 −2.00%、000559 −1.51%、002181 −0.45%；组均 −4.06%，组均超额 −1.98pp（等权 −2.083%）。
- 当日 `regime=stressed`（20 日实现波动 31.5%、近一年 91% 分位）、宽度 0.274、跌停 39 家、`tone=退潮`。「低开 0~2% 是情绪不是利空」这条前提，在宽度打穿 35% 的日子里不成立：全市场在失血时，低开不是错杀，是第一步。
- v2 下这 6 只被 500 元额度全挡（制度性），6/6 都对；v3 拆掉额度后，如果没有这条闸，其中 1 只会真的进仓。

## 验收与作废

- **验收判据**：被闸日里那批票的**净**超额（`quant_declined` 的 `mean_excess`，不用单日涨跌）。
- **样本门槛**：累计 **3 个被闸日**、每个被闸日 **≥3 只**、总 **n ≥ 9** 才判。
- **作废条件**：连续 3 个被闸日的组均净超额 **> +1pp** → 闸失效，回退为「放行路每日 1 只」。
- **不触发时**：3 个交易日内一次未触发，照实记「闸未触发」，不得事后把普通日算作被闸日。

## 边界

- 不修改风控、T+1、涨跌停、现金约束、单票上限中的任何一项；只决定这条**入口**在当前市场状态下是否存在。
- 不影响 `0 < x ≤ 3%` 档（赔率门）与 `x > 3%` 档（§8.3 累计至 n=10）。
- 与 §8.4 的「−2%~0 档连续 3 日组均超额 ≤ −2pp 则回退为一票否决」并列存在，不互相替代：§8.4 管事后，本条管事前。
