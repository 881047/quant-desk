# 规则书：哪一份在生效，哪些只是历史

`quant_playbook` 只返回 `meta.json` 里 `active` 指向的那**一份**。同目录下的其他文件
留在仓库里是为了追溯——**不要执行**它们；它们的窗口、阈值、仓位都可能已经过期
（例如 v1/v2 的收盘窗口还叫 14:35，现行是 14:30）。

| 文件 | 状态 | 生效区间 | 这一版改了什么 |
|---|---|---|---|
| `v1.md` | 历史 | 2026-10-25 → 2026-11-09 | 初版 |
| `v2.md` | 历史 | 2026-11-09 → 2026-11-13 | §7 窗口与权限、§8 跳空分档、§9 档位不许用 T-1 |
| `v3.md` | **现行** | 2026-11-13 起 | 成本分档、§1 作废、单票上限统一 50%、赔率门改「经济+证据」、§9.6 过门即过门 |

## 生命周期

1. 改动先 `quant_playbook_propose(text, note)` 写进 `drafts/`，**不生效**；
   人工激活后才成为新版本，旧版本原样留在原地作为历史。
2. `meta.json` 是唯一状态源：`versions[]` 记 `created_at` / `note`，`superseded[]` 记
   被并入的草案与并入理由。
3. 只统一措辞、不改条款的就地修订记 `amended_at` / `amend_note` 而不是升版
   ——v2 统一过版本表、v3 把收盘窗口 14:35 对齐到 14:30，都是这一类。

## drafts/

| 文件 | 状态 |
|---|---|
| `pb-20261113193436-e37f3d.md` | **待激活**：§8.2 放行路加市场状态闸（阈值用内核已有定义） |
| 其余 4 份 | 已被 v2 / v3 吸收，见 `meta.json` 的 `superseded`，原文保留备查 |

`quant_playbook.drafts` 非空只表示**有人提了改动**，未激活的不生效；
`is_fragment=true` 的草案是补丁，激活会把规则书覆盖成残页，不要建议激活。
