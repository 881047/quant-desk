# 工具能力审计 · 短线交易分析视角

> **历史快照，不是现行规范。** 审计时 62 个工具，现在 67 个；那一版的字段名与口径
> （如 `opened_intraday`）此后已拆改。读它只为追溯「当时为什么这么设计」，
> 现行结论看工具描述与 `docs/00-README.md`。

> 审计日期：2026-11-02（周一，盘中 09:30–13:22）
> 审计对象：`plugin/` 下的 `quant_*` 工具（审计当时 62 个，以 `plugin/lib/index.js` 的 `buildTools()` 为准），及 `scripts/external.py`
> 触发场景：一次真实的重仓交易（实盘 300 股 002602，79% 仓位），全流程暴露工具边界
> 结论先行：**今天所有判断失误，没有一次源于工具算错，全部源于"看到的数据是旧的"或"该看的口径没有被提供"。**

## 0. 摘要

| 类别 | 条数 | 最严重的一条 |
|---|---|---|
| 数据时效 | 5 | 涨停池是 10:30 快照，我在 13:18 仍在引用 2.8 小时前的封单额 |
| 数据覆盖 | 4 | 实盘持仓对内核完全不可见，`quant_stops` 返回"没有持仓" |
| 能力缺口 | 4 | 没有盘口（封单、委比、内外盘），打板分析缺第一手数据 |
| 可用性 | 2 | `quant_bars` 请求 250 天只返回最早 12 行 |
| 方法论 | 2 | 用机构口径（行业主力净流入）判断游资行为 |

**最危险的一条不是精度问题，是监控盲区**：账户 79.4% 仓位持有一只内核看不见的票，从 13:00 到收盘没有任何自动告警。

## 1. 缺陷清单

### P0 · 直接影响当日资金决策

#### P0-1 涨停池为快照且无刷新机制

**证据**

```
quant_pools → pool_state.loaded_at = "2026-11-02T10:30:12+08:00"
               pool_state.now       = "2026-11-02T13:18:39+08:00"
```

**影响**：12:36 至 13:18 共 6 次引用该快照的 `seal_amount`（封单额）与 `open_times`（开板次数），最长滞后 2.8 小时。13:03 给出的"东方海洋封单 2.62 亿 / 成交 5.08 亿 = 51.6%"结论，实际数据可能已完全变样。

**根因**：池子按 `quoted_date` 缓存，命中同日即返回，未校验 `loaded_at` 的时效。

**改法**

- `quant_pools(force_refresh: bool = false)`
- `loaded_at` 超过 `stale_after`（建议 600 秒）时，在响应顶层加 `stale: true` + `age_seconds`，与 `quant_quote` 的 `age_seconds` 口径统一
- 超过 1800 秒直接拒绝计算衍生指标（如封单/成交比），或标注 `derived_from_stale: true`

**验收**：13:30 调用时，`loaded_at` 距 `now` ≤ 600 秒；若上游失败，返回 `stale: true` 而不是静默复用。

---

#### P0-2 盘中三池未入库，涨停结构不可得

**证据**

```
quant_limit_structure(as_of=20261102)
→ counts.limit_up = null, seal_rate = null, max_streak = null, tiers = {}
→ notes: "20261102 的涨停/跌停/炸板池尚未入库；先跑 fetch_ths_special.py"
```

**影响**：无法实时取得全市场涨停家数、封板率、连板天梯。12:41 至 13:18 的分析中，所有"涨停 48 家""炸板率 21.3%"均来自 `quant_pools` 的 10:30 快照，而非当日终值。判断"情绪是否崩塌"只能逐只个股比对涨停价，无法做全市场统计。

**改法**：把 `fetch_ths_special.py` 纳入盘中定时任务。

```
10:00  11:00  13:30  14:30  14:55
```

`14:55` 那次为收盘前最后一次，用于尾盘情绪判定。

**验收**：盘中任意时刻调用 `quant_limit_structure`，`counts.source` 为 `derived:limit_pool_t0` 或注明当日未入库的原因，不再返回全 null。

---

#### P0-3 实盘持仓不在内核视野内（**最高优先级**）

**证据**

```
quant_stops()        → {"stops": [], "note": "没有持仓，所以没有止损"}
quant_watch()        → checked.positions = 0
实盘 external.sqlite → 601857 卖出于 13:0x，买入 002602 300 股
```

**影响**：13:00 至收盘，账户 79.4% 仓位（3,705 / 4,667 元）没有任何自动止损监控。当日给出的关键位（11.74 硬止损、11.90 清仓、12.09 低开走）全部依赖人工盯盘。**这是今天唯一可能造成不可逆损失的系统性缺口。**

**根因**：`quant_stops` 只读模拟盘 `paper.sqlite`，实盘账本 `external.sqlite` 是平行的只读体系（见 `AGENTS.md`「实盘（账外）与提醒」）。

**改法**

- `quant_stops(account: "paper" | "external" = "paper")`，实盘路径复用 `scripts/external.py` 的持仓聚合与费用口径
- 止损基准改为可配置：当前规则写死 `买入价 × 0.95`，需支持 `stop_rule: "pct5" | "atr" | "custom"`，以便写入 11.74 这类按风险预算反算的价位
- `quant_watch` 的 `checked.positions` 应区分 `paper_positions` / `external_positions`

**验收**：`quant_stops(account="external")` 返回 002602 的 `cost=12.367 / stop=11.74 / distance_pct`，并进入 `near_stop` 告警链路。

---

#### P0-4 `external.py report` 静默用成本价兜底

**证据**

```
2026-11-02 13:00 实际输出：
  601857.SH  现价 13.62   ← 同期实测 13.86
  600814.SH  0股  现价 0.00  ⚠️ 破止损   ← 已清仓标的仍报破位
  总盈亏 +0 (+0.00%)
```

**影响**：13.62 与成本价 13.617 几乎重合，说明行情取数失败后回落到成本价，且未作任何标注。若以此价计算止损距离，会把止损锚到错误的价位上——这与 `AGENTS.md` 里"一次读错会把止损锚到错的价格上"的告诫同一性质。同时，0 股的已清仓标的出现在持仓列表并触发"破止损"，会污染告警。

**改法**

- 取价失败 → 抛 `PriceUnavailable`，输出 `price_source: "unavailable"`，**禁止用成本价代替现价**
- 持仓聚合过滤 `qty == 0` 的行
- 报告头部增加 `price_source` 与 `as_of` 字段

**验收**：断网情况下跑 `external.py report`，返回明确错误而非 0 盈亏。

### P1 · 影响分析质量，不直接造成损失

#### P1-1 指数不支持实时报价

**证据**：`quant_quote(symbols="000001.SH,000300.SH,399001.SZ")` → 仅返回 `399001.SZ`，上证与沪深300 缺失。`399001.SZ` 走 tencent 源可用。

**影响**：无法用工具计算"个股 vs 大盘"的相对强度。13:14 判断"世纪华通跑输/跑赢"时，上证指数需外部检索获得。`history()` 已按 `configs/data.json` 的 `index_codes` 切到 `index_daily`（见 2026-11-01 修复记录），但 `quote` 层未同步。

**改法**：`quote` 的指数分支复用 `index_daily` + 实时源，或单独提供 `quant_index_quote`。

**验收**：`quant_quote("000001.SH")` 返回 `last/pre_close/pct_chg/amount`，`source` 明确。

---

#### P1-2 无申万行业榜

**证据**：31 个申万一级行业的涨跌幅与主力净流入，当日全部来自外部数据商，非 `quant_*` 提供。

**影响**：板块层面的"哪条线有资金"这一判断，内核无法支撑。当日传媒 +6.69%／+29.99 亿、非银 +3.02%／+27.94 亿、银行 -0.65%／-11.06 亿等关键数据均为外部来源。

**改法**：新增 `quant_sector`

- 涨跌幅：读 `data/parquet/index_daily` 的申万行业指数
- 资金：`moneyflow` 按行业聚合（注意 T+1 限制，需在响应中标注 `as_of`）

**验收**：`quant_sector()` 返回 31 行，字段含 `sw_l1 / pct_chg / main_net_inflow_cny / as_of`。

---

#### P1-3 无盘口字段

**证据**：`quant_quote` 返回 `last/open/high/low/volume/amount/up_limit/down_limit/pct_chg`，无 `bid1_volume` / `ask1_volume` / `wb_ratio`。

**影响**：打板分析的核心是封单强度及其变化率。涨停时买一量即封单量，是最直接的一手数据；当日只能依赖 2.8 小时前的池子快照。此外 13:10 判断"委比 -43.42%"的数据来自外部检索，非工具。

**改法**：`quant_quote` 增加 `bid1_volume`、`ask1_volume`、`limit_state ∈ {sealed, opened, one_word, none}`。

**验收**：涨停股返回 `limit_state="sealed"` 且 `bid1_volume > 0`；开板瞬间 `limit_state` 变 `opened`。

---

#### P1-4 无分时数据入口

**证据**：`data/parquet/stk_mins` 存在，但无工具暴露。当日判断"缩量回落 vs 放量派发"仅能用两个时点的 `amount` 差值近似（如 13:10→13:14 差 0.17 亿，折算 2.55 亿/小时）。

**改法**：`quant_mins(symbol, date)` 返回分钟级 OHLCV，或提供 `quant_intraday_profile` 返回分时量价摘要。

### P2 · 可用性与方法论

#### P2-1 `quant_bars` 截断方向错误

**证据**

```
quant_bars("601857.SH", days=250)
→ bars 数组只返回 20251021 起的 12 行
→ _shrink: { level: 1, rows_cut_at: 12, rows_dropped: 238 }
```

**影响**：数据完整存在，但返回的是**最早** 12 行，最近的行情取不到，工具事实上不可用。当日改用本地 `data/parquet/daily` 绕过。

**改法**：截断时保留**末尾** N 行（贴近当日），或提供 `tail=true` 参数。

**验收**：`quant_bars(days=250)` 返回的最后一行 `trade_date` 等于 `last_bar`。

---

#### P2-2 数据源稳定性

**证据**

```
quant_market_status → breakers.eastmoney.open = true
                      consecutive_failures = 5
                      last_error = "GET push2.eastmoney.com ... Server disconnected"
                      breakers.ths.last_error = "RuntimeError: code=3001 Target not found"
```

**影响**：东财源当日熔断，涨停池因此只有 10:30 那一次成功抓取；同花顺个别标的查询报 `code=3001`。多源冗余存在但降级路径未在响应中标明"当前只有 N 个源可用"。

**改法**：`quant_quote` 响应体现 `source` 已实现，补充 `degraded: true` 与 `available_sources`。

---

#### P2-3 方法论：机构口径与游资口径混用

**证据**：12:41 的板块分析中，以"医药生物主力净流入 -4.42 亿"否定医药方向。而当日澳洋健康（002172）4 连板封住、成交 12.14 亿、封单/成交比在全部可买标的中最高。

**性质**：这不是工具缺陷，是使用者的口径错误。但工具可以在字段层面降低误用概率。

**建议**

- `moneyflow` 字段说明显式标注："本口径为大单/超大单净额，**不包含营业部席位**，不能用于判断游资行为"
- 文档中固化两条分析线：

| 资金性质 | 观察指标 | 工具 |
|---|---|---|
| 机构线 | 行业主力净流入、成交额占比 | `quant_sector`、`moneyflow` |
| 游资线 | 连板高度、首封时间、封单/成交比、开板次数 | `quant_pools`、`quant_limit_structure` |

**两条线的指标不可交叉使用。**

---

#### P2-4 `quant_pools` 缺行业分组

**影响**：当日需回答"医药有几只连板"，只能逐只手工数。建议 `group_by: "industry"`，直接返回板块内连板梯队。

## 3. 改进优先级与工作量

| 编号 | 项目 | 优先级 | 预估改动量 | 依赖 |
|---|---|---|---|---|
| P0-4 | external.py 取价失败报错 | P0 | 20 行 | 无 |
| P0-1 | pools 快照时效校验 | P0 | 60 行 + 1 参数 | 无 |
| P0-2 | 盘中跑 fetch_ths_special | P0 | 计划任务配置 | 上游可用 |
| P0-3 | 实盘接入 quant_stops | P0 | 200 行 | P0-4 |
| P1-3 | quote 增加盘口字段 | P1 | 80 行 | 数据源支持 |
| P1-1 | 指数 quote | P1 | 100 行 | index_daily |
| P1-2 | 新增 quant_sector | P1 | 250 行 | index_daily + moneyflow |
| P2-1 | bars 尾部截断 | P2 | 10 行 | 无 |
| P1-4 | 分时入口 | P2 | 150 行 | stk_mins |

**建议执行顺序**：P0-4 → P0-1 → P0-3 → P0-2 → P1-3 → P1-1 → P1-2 → P2-1 → P1-4

理由：前四项是"花钱时会痛"的缺陷，后五项是"分析质量"缺陷。P0-4 只有 20 行改动，却是 P0-3 的前置。

## 5. 一句话

**工具的精度没有问题，问题在于"这一刻"与"我看到的这一刻"之间的时间差，以及"我该看的那个口径"根本没被提供。** 前者用刷新与时效标注解决，后者用新增字段与工具解决。而最该先做的，是让内核看得见实盘那 300 股。
