# 08 — 三种人格与一个显式选择层

日期：2026-10-26
代码：`service/trading/persona.py`、`scripts/daily_job.py`、`service/trading/attribution.py`

---

## 1. 问题：风格选择一直是隐形的

内核给事实，模型给判断。但"用什么风格判断"这件事以前没有位置：
它藏在提案的散文里，事后无法归因，无法评分，也无法被否决。

结果是三种完全不同的行为共用一个账本：

- 追连板、1 天必须了结的**游资**行为；
- 买跌不动的、10–60 日持有的**散户**行为；
- 等一个催化、1–5 日兑现的**交易员**行为。

一个 +0.14% 的账户收益率，无法回答"这是哪种风格赚的、还是运气"。
本文件把风格变成一等对象：有 sleeve、有周期、有数据前提、有账本、有切换记录。

---

## 2. 三个角色

| key | 名称 | 可用 sleeve | 周期 | 状态（regime） | 数据前提 |
|---|---|---|---|---|---|
| `hot_money` | 游资 | AGGRESSIVE | 1–2 日 | risk_on / neutral | 实时报价 + 盘面结构 + 情绪面板 |
| `retail` | 散户 | CORE | 10–60 日 | neutral / risk_off / stressed | 日线 |
| `trader` | 交易员 | CORE + AGGRESSIVE | 1–5 日 | 全部 | 日线 |

每个角色都写死 `why_not`——**什么情况下这个风格不该用**。这不是装饰：
游资在情绪冰点、炸板率 >35%、最高板 <3 时历史超额最差；散户在 risk_on 里
必然跑输；交易员在没有催化时有把随机波动包装成故事的风险。

三者的证据都来自已经跑完的判决，不是印象：

- 游资：P5–P24 九个短线结构全部 `rejected`，最好毛边 0.30%，而 ¥5,000 账户
  盈亏平衡线 0.85%/笔。**但那些判决测的都是 `next_open`（次日开盘接力），不是这条
  人格做的「T 日封板买入」**——`spec.py` 在 2026-11-03 之前只有 `next_open` /
  `next_close` 两种入场，打板这个入场点根本表达不出来。本地实测（2023-01~2026-10，
  首板 n=44,705）：T 收→T+1 收 +1.75%，其中隔夜段 +2.00%、T+1 日内 −0.22%——
  钱在隔夜，而隔夜那一段当时不可测。所以 `rejected` 保留，但它关闭的是"次日接力"，
  **不是**"打板"；要关闭后者，先用 `entry=t_close` 重跑。
  它的门禁是四条独立条件（tone / 炸板率 / 最高板 / 实时报价），
  `/market/pools` 的 `gates` 逐条返回，因为"情绪冷"和"情绪热但没高度"是两个不同的决定；
- 散户：核心盘规则有 2019–2025 回测（CAGR 9.6%、Sharpe 1.33、MDD -8.3%），
  但那是 ETF 轮动规则的证据，**不是**自由裁量风格的证据；
- 交易员：1 笔持仓、0 笔平仓，arena 判 `insufficient`。

## 3. 切换协议

`POST /persona/switch`（工具 `quant_persona_switch`）必须带四样东西：

| 字段 | 为什么必须 |
|---|---|
| `reason` | 你看到了什么（≥20 字） |
| `evidence[]` | 在哪看到的（至少一个 evidence id） |
| `expected_edge_bps` | 你认为这次换风格值多少个基点 |
| `invalidation` | 什么会证明你错了（≥5 字） |

**没有 `expected_edge_bps` 与 `invalidation`，切换就无法被结算**，
"哪个风格收益最大就换哪个"就成了一句无法证伪的口号。协议在 422 层面拒绝
这种切换，不是靠提示词劝导。

约束：

- 同一交易日最多 2 次（`SWITCH_LIMIT`，429）。第 3 次通常不是重新分析，
  是把当天的亏损换一种说法；
- 不能切到当前已在运行的角色（`SAME_PERSONA`，409）；
- 数据前提缺失时**允许切换但标记 blocked**，因为盘后预置明天的人格是合理的；
  但下单时会被 `409 PERSONA_NOT_READY` 拒绝——盘后用日线价成交等于把回看写成成交；
- 与 regime 不匹配**只警告不阻断**。内核报告"这个状态历史上没有理据"，
  但判断权仍在模型；那一笔切换本身需要额外证据。

## 4. 提案闸门

`/decision/propose` 新增 `persona` 字段，三条规则：

1. 必须等于当前活跃人格，否则 `409 PERSONA_MISMATCH`。换风格要显式记录，
   不能在提案里偷偷改标签。
2. 人格必须允许该 sleeve，否则 `PERSONA_SLEEVE`（游资不能花 CORE 的钱）。
3. 人格的数据前提必须齐，否则 `PERSONA_NOT_READY`。

**卖出不受这三条限制。** 清仓是风险动作，不是风格选择。

## 5. 结算：切换本身是一个要被检验的策略

`GET /persona` 的 `scorecard` 把每次切换之后的账户收益，减去同期等权市场：

```
excess = (1 + 切换后收益) / (1 + 同期等权收益) - 1
beat_expectation = excess×10000 >= expected_edge_bps
```

这是本模块唯一读净值的地方，而且只在事后。`suggest()` 有测试保证
**看不到 nav / equity / pnl**——一个能读收益的选择器，迟早会被在收益上优化。

样本按设计很小：每天最多 2 次切换，一条切换不足以说明选择器有效。
它的作用是让"换人格"从叙事变成可被推翻的命题。

## 6. 设计红线：代码不选人格

`suggest()` 只做两件硬筛：

- 数据是否齐（`probe`）；
- regime 是否对口（注册表）。

筛完给候选，不给排序，不给推荐。**自动按收益轮换人格是被明确拒绝的设计**：

- 2026 年的 rotation 文献（MSIH-VAR 类）显示，regime 分类的样本外一致性
  远高于行业/风格的命中率——宏观状态能解释大环境，解释不了高频轮动；
- Swingfolio 的规则更直接：**在入场时记录状态，事后不得改写**。若标签是
  看了结果才贴的，每个赢家都会像趋势、每个输家都像坏状态；
- 2026 年国内头部量化的实际应对是"严控风格暴露、专注纯 alpha"，不是追风格。

所以：**任何自动轮换都属于 `service/research`，要过和十个被证伪结构同一套裁判，
不能长在执行路径上。** `tests/trading/test_persona.py` 有守卫：
`persona.py` 里不得出现 `auto_switch` / `rotate(` / `pick_best` / `argmax`。

## 7. 外部依据

- **MetaPS**（arXiv:2606.22385, 2026-06）把这件事说透了：LLM 应当做**策略选择器**
  而非动作生成器；选择层可单独回测，执行层保持确定性。本模块对应它的 router 层，
  内核的 guard 对应执行层。
- **TradingAgents 类框架**报告的高收益是回测数；arXiv 2505.07078 / 2605.28359
  显示控制"记忆泄露"后表观技能急剧缩小。人格层不产生 alpha，只让"用哪种逻辑"
  这件事变得可审计——这与"结构买的是可审计性，不是 alpha"的结论一致。

## 9. 同批修复：核心盘净值

`CoreBook.record_nav(as_of)` 现在每个交易日写一行，**空仓日也写**。

此前只有 `execute()` 路径写净值，于是一个正确地保持现金的账本没有任何记录，
而 `/decay` 对唯一有样本外证据的策略（core_etf）永远报 `insufficient`——
它的业绩曲线只在"恰好交易的那天"存在，那是选择效应，不是记录。

两条防护，都是"不写看起来合理的假话"：

- 当日没有 ETF bar → 不写（拖尾价格会让今天复制昨天的净值）；
- `as_of` 早于库中最后一行 → 拒绝，因为 `state()` 是今天的持仓，
  补历史等于用今天的账本给昨天估值。

`scripts/daily_job.py` 已接入（第 5.5 步），失败不打断日更——净值是一行测量，
不是依赖。
