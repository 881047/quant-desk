### `ProposeBody`

用于 `POST /decision/propose`、`POST /samples/propose`。

| field | type | required | constraints |
|---|---|---|---|
| `symbol` | string | yes | minLength=6, maxLength=12 |
| `side` | enum("BUY", "SELL") | yes | — |
| `sleeve` | enum("CORE", "AGGRESSIVE") | no | default="CORE" |
| `intent_type` | string | no | maxLength=60, default="unspecified" |
| `thesis` | string | yes | minLength=20, maxLength=1200 |
| `evidence` | string[] | yes | minItems=1, maxItems=8 |
| `invalidation` | string | yes | minLength=5, maxLength=500 |
| `client_request_id` | string \| null | no | — |
| `target_weight` | number \| null | no | — |
| `qty` | integer \| null | no | — |
| `strategy` | string | no | maxLength=30, default="llm" |
| `directed_by` | enum("agent", "user") | no | default="agent" |
| `persona` | string \| null | no | — |
| `contingency` | object \| null | no | — |

字段说明：

- `symbol`：600000.SH
- `client_request_id`：调用方生成的幂等句柄。**超时重试必须原样带上同一个值**：同一个 id 永远返回同一张票（包括已被拒绝或已成交的那张），所以重试不会扣两次钱、也不会变成两张票。省略则退回按意图指纹去重，而指纹含 thesis/evidence 的自由文本——换个说法就是第二张票。
- `qty`：股数。与 target_weight 二选一：一个说买多少股，一个说占多少仓位。买入时仍受合法手数、单票上限、单笔风险预算约束；卖出时表示减仓数量，省略即清仓。
- `directed_by`：谁下的这个决定：agent = 模型自己的判断；user = 用户明确指令。用户指令平掉的仓位照常记账，但**不计入 arena 的 edge 统计**——它测的是那条指令，不是判断力。
- `persona`：必须等于当前活跃人格；换风格先 POST /persona/switch
- `contingency`：入场意图的条件单（意图层）。trigger.observe 或 trigger.enabled 任一为 true 时允许提交；两者都关时提交会被 TRIGGER_DISABLED 拒绝并写 proposal_blocked 留痕，绝不静默丢弃。只开 observe 时票冻结成 armed、逐帧求值写 reports/shadow 轨迹，二次 approve 也不会出钱；只有 enabled=true 才由盯盘循环兑现同一张票。手工二次 approve 一律被守卫拒绝（只返回 armed 并附 note），条件终态为 expired_untriggered / denied 或已越过 valid_until 的票不得复活。字段：kind(price|frame_time)、op(lte|gte|eq)、value、valid_from、valid_until、max_triggers=1、on_expiry=mark_only。带上条件后，首次 approve 只把票冻结成 armed（不出钱、不进撮合队列）；条件被捕获帧命中时，盯盘循环兑现的是**同一张票**。armed 票可用 reject 或 cancel 主动撤销，两入口都置 status=cancelled、不出钱、不动 ledger；条件越过 valid_until 后记 expired_untriggered 并释放指纹去重槽位，但票状态仍由跨日 expired 裁决。

## Paths that do not exist (and what to use instead)

Every row below has been called by a model at least once, returned 404,
and been retried. They are listed so the next attempt stops here.

| wrong | use | why |
|---|---|---|
| `POST /decision/approve` | `POST /decision/{ticket_id}/approve` | the ticket id is a path segment, not a body field |
| `POST /decision/cancel` | `POST /decision/{ticket_id}/cancel` | the ticket id is a path segment, not a body field; cancel withdraws a QUEUED order (and an ARMED intent), while reject closes a PROPOSAL; on an armed intent both routes set status=cancelled without spending money |
| `POST /core/rebalance` | `POST /core/plan then POST /core/execute` | P19 removed automatic rebalancing; the plan is advisory until executed |
| `POST /risk/stops/enforce` | `POST /decision/propose with side=SELL` | P15 removed the /risk/stops/enforce route; selling still goes through /decision/propose. The kernel places no new-judgement orders, but a stop written on the entry ticket is executed by the capture loop through propose + approve once a breach has persisted autostop.confirm_seconds (configs/params.yaml autostop.enabled turns it off) |

## 4xx means stop

| status | meaning | what to do |
|---|---|---|
| 401 | missing or wrong `X-Quant-Token` | read `.env`, do not retry |
| 404 | the path does not exist | look it up in the table above |
| 409 | the guard refused the decision | read `reasons`; changing the body will not help |
| 422 | the body has fields the schema does not accept | send only the fields listed under Request bodies |
| 429 | this path failed 30+ times in 60s | stop, read `/openapi.json` |

A rejected proposal is recorded, not erased: `tickets` keeps
`status="rejected"` and `decisions` gets a `reject` row. But it is not
a live order — there is nothing to approve, and the same
`client_request_id` keeps returning that refusal instead of running
the guard again.

## Tables outside the schema

These exist in `data/paper.sqlite` but not in `state.DDL`. Almost always a
deleted feature whose table was never dropped: the code is gone, the rows
stayed. Nothing reads them, nothing expires them, and no guard applies —
which is exactly why they are listed here instead of being ignored.

None. Every table in the file is declared in `state.DDL`.
