# 双向信息内核：从"只会说不"到"能说是，并且刻度可信"

版本：2026-10-26 ｜ 状态：**P20–P25 已实施，P26 为设计** ｜ 前置阅读：`06-kernel-as-knowledge.md`

---

## 0. 一句话诊断

**证伪侧有一台能跑的实验台，真 alpha 侧没有通道；而这台实验台本身的刻度从未校准过。**

九个短线结构全部否定，这个结果在观测上与"裁判坏了"不可区分。在没有正控之前，
`rejected` 只能读作"未通过本 gate"，不能读作"市场无 alpha"。

---

## 1. 现状：证据链只有一半

| 环节 | 证伪侧 | 真 alpha 侧 |
|---|---|---|
| 流程 | 有：`spec → grid → DSR/PBO/CPCV → cost stress → verdict` | 无：只有人工写 hypothesis + 影子盘 |
| 刻度 | 无：从未证明能录取真信号 | 无：`promoted` 从未发生过一次 |
| 计数 | 只有单次 `run()` 的 grid（8–16 个变体） | 无跨假设累计，每次 run 重置分母 |
| 归因 | 只有等权市场超额 | 无因子残差，无 per-strategy realized |
| 判决后 | 无 | ✅ P25 已补：CUSUM / 滚动 z / SPRT 三路 + 状态机 |

外部同类做法（2026-10）：arXiv 2610.07701 把这件事命名为 **injected-truth protocol +
random-admission control**——只有当 gate 的录取率显著优于"同录取率的随机抽样"时，
gate 才携带信息，否则它只是抬高了一道门槛。这正是当前缺的那一步。

## 2. 七个缺陷（按"会不会改变结论"排序）

### 2.1 裁判没有正控（最致命）

无法回答："如果历史上真有一个 +0.5%/笔的结构，这套 gate 会不会录取它？"

论文的两条结论对你有直接约束：
1. gate 在弱信号区能杀假，在强信号区不增益；
2. 用绝对收益而非超额做判据，会把真信号一起杀掉。

你的 `excess` 口径是对的（相对等权市场），但从未验证过。**校准之前，所有
rejected 的置信度未知。**

### 2.2 成本口径有三套，且研究层最松

| 位置 | 实现 | 参数 |
|---|---|---|
| `kernel/costs.py` | 佣金 0.025%（最低 ¥5）+ 卖出印花税 0.05% + 过户费 0.001% | ETF 免印花税/过户费 |
| `trading/core.py::_fee` | `max(5, notional×0.00025)` | 只有佣金，硬编码 |
| `research/spec.py` | `cost = 2 × cost_bps / 10000`，默认 10bps/边 | 无最低佣金、无印花税 |

按内核费用模型实算（¥5,000 账户，单票金额 → 真实往返成本，含 10bps/边滑点）：

| 单票金额 | 费用往返 | +滑点 | 研究默认 20bps | 2× 压力 40bps | 3× 压力 60bps |
|---|---|---|---|---|---|
| ¥500 | 205bps | 225bps | 11× 低估 | 5.6× | 3.8× |
| ¥1,000 | 105bps | 125bps | 6.3× | 3.1× | 2.1× |
| ¥2,000 | 55bps | 75bps | 3.8× | 1.9× | 1.25× |
| ¥4,000 | 30bps | 50bps | 2.5× | 1.25× | 0.83× |
| ¥5,000 | 25bps | 45bps | 2.25× | 1.1× | 0.75× |

三个直接后果：

1. **"3× 成本压力"对任何 ≥2 只持仓的组合都不是压力**。¥1,000×5 只的真实成本
   125bps，是 3× 压力（60bps）的两倍。
2. **已 rejected 的结论因此更硬**：在低估 2–6 倍的成本下都没过。
3. **唯一 testing 的候选在真实成本下必然为负**：+0.30%/笔 × 302 笔 = 总收益 +0.9%，
   而每笔多付 25–105bps 就抹掉 0.75–3.2 个百分点。

这条也解释了为什么只有 ETF 核心活下来：它是唯一"每笔预期 >2%、每年换手 <20 次"
的结构，成本占比 <5%。其余九个都在成本否决区。

> **P21 已修（2026-10-26）**：研究层改调 `kernel.CostModel` 逐笔计费，票面按
> `min(权益, max(权益/信号数, 一手))` 推导，`cost_mult` 现在乘"手续费+滑点"全部成本。
> 10 个 preset 重判：**2 个从 `testing` 变 `rejected`，仓位表里 0 个 testing**。
> 唯一候选（正股跌停→转债）从 +0.298% 变 **+0.098%**，p 0.078→0.339（仍为正，但只有盈亏平衡线的 1/8.7）。
> 详见 `reports/P21_cost_unification.md`。

### 2.3 p 值口径偏乐观 ✅ P24 已修

`_trade_stats` 原来用 IID bootstrap 对 trade-level excess，`block_bootstrap_pvalue`
写好了却无人调用。P24 改为**按日聚合成日收益再 block bootstrap**（`p_basis="day-block(Nd)"`）。
10 个 preset 的 p 变动 ≤0.014、判决一个没变，但区间宽度差 √(笔/天)（44.5 笔/天时约 6.7 倍）。
旧的 dead code 现在是被调用的实现。

正确做法：按 `entry_date` 聚合成日收益再 block bootstrap，或 cluster bootstrap by day。
方向：当前 p 被低估 → 更容易"显著"；即便这样仍全灭，说明结论方向不变，但那个
`p=0.078` 更不可信。

### 2.4 试验次数被系统性低估

`_grid()` 只展开 boards × entry × hold × exit（cb_link 那次是 8 个）。未计入的
研究者自由度：`start/end`、`min_amount`、`max_per_day`、`rank_by/rank_dir`、
`gap_threshold`、`exclude_st/bj`。真实规格数至少 ×10–×50。

E[max SR] 按 √(2 ln N) 增长（Bailey–López de Prado）：

| N | E[max SR] / σ_SR |
|---|---|
| 8 | 1.46 |
| 45 | 2.27 |
| 500 | 3.05 |

**光是把计数改诚实，Sharpe 1.07 的那个候选就会从 `testing` 变 `rejected`。**

更严重的是**没有全局分母**：每次 `run()` 都重置 trials。在同一份 2023–2026 数据上
跑 9 条假设、每条按 8 次试验 deflate，等于把 72 次搜索当成 8 次。

跨假设的最强证据：9 个检验里最好 p=0.078。9 个独立零假设下至少出现一个 p<0.10 的
概率是 **61.3%**；BH-FDR（q=0.10）对最小 p 的门槛是 0.0111。**那个候选与"你预期
会看到的那一个假阳性"在数值上完全无法区分。**

### 2.5 没有因子中性化

基准只有等权市场。九个结构全部围绕涨停/跌停/炸板，天然带高 beta、小市值、强反转
暴露。所谓"超额"里混着这些。应先对 beta / size / reversal / liquidity 回归，再看
残差 alpha 的 t。

### 2.6 没有功效分析（决定 `testing` 是否可行动）

`MIN_TRADES = 100` 是拍的。302 笔、每笔 σ≈6%，80% power、单侧 α=0.05 下：

```
MDE = 2.485 × σ / √n = 2.485 × 6% / 17.38 ≈ 0.86%/笔
```

是观测效应 +0.30% 的 **2.9 倍**（σ 在 4%–8% 区间时是 1.9–3.8 倍）。
要判定 0.30%/笔，需要约 **2,500–4,400 笔**。

**那个 `testing` 判决不是"证据不足"，是"按当前规则证据不可能足够"。**
这类结论应该有自己的名字：`underpowered`，而不是和"多跑点数据再说"混在一起。

### 2.7 内核域模型缺两个字段（执行侧唯一硬缺口）

| 缺什么 | 后果 |
|---|---|
| `Fill.ref_price`（成交时参考价，如 bar open） | 无法算 implementation shortfall / TCA，无法区分"信号错"与"滑点贵" |
| `Intent/Order/Fill.strategy_id` | 账本无法按假设归因，realized alpha 无从统计 |

`book._record_fill` 里的 `strategy` 是票据层自由文本，内核域对象不认；`sleeve` 只有
`CORE/AGGRESSIVE` 两档。**没有这两个字段，"真 alpha"通道在数据模型上就不存在。**

### 2.8 promoted 之后没人看管

影子盘记录了 NAV，但没有把"实际 Sharpe vs 回测分布"做成检验，也没有 CUSUM/SPRT。
真 alpha 会衰减；没有衰减检测的 alpha 通道是一次性的。

## 3. 目标架构：六个组件 + 一次字段升级

| # | 组件 | 位置 | 接口 | 验收标准 |
|---|---|---|---|---|
| 1 | ✅ 注入真值校准 | `research/controls.py` | 合成面板 α ∈ {0, +0.2%, +0.5%, +1.0%} + placebo；随机录取对照 | **实测**：α≥+0.5% TPR 100%，α=0 FDR 0%，placebo 0%，lift +60% |
| 2 | ✅ 成本统一 | `research/spec.py` | 直接调 `kernel.CostModel`，逐笔按票面金额计费；`cost_mult` 乘全部成本 | **实测**：¥1,000 票 125bps / ¥5,000 票 45bps；判决返回 `cost_bps_effective`；3 个 testing 变 rejected |
| 3 | ✅ 全局试验登记 | `research/registry.py` | 每次 run 写 `(spec_hash, n_variants, n_looks, p, effect)`；DSR 分母 = 族内全部搜索 | **实测**：10 runs = **124 searches**；min p 0.339，FDR 1.0，0 survivors |
| 4 | ✅ 因子匹配 | `research/attribution.py` | 同日特征近邻（市值/beta/反转/流动性），**不估系数** | **实测**：残差 +0.13%/笔、t 0.6–0.7；`t<2` 直接拦下；k=10/20/40 稳定 |
| 5 | ✅ 功效 | `research/power.py` | MDE / required days / `underpowered` 判决 | **实测**：10 个 preset 的 MDE 18–70bps，门槛 80–228bps，**无一 underpowered** |
| 6 | ✅ 衰减监测 | `trading/decay.py` | CUSUM + 滚动 z + SPRT；逐笔与 NAV 两种口径 | **实测**：`core_etf` 有基准但 0 天 → `insufficient`；输出无任何 action 字段 |
| 7 | ⚠️ 部分落地 | `kernel/models.py` | 已实现 `Fill.ref_price`、`Fill.limit_up_penalty`；**未实现** `Fill.strategy_id` / `Intent.strategy_id` / `CostModel.effective_bps()` | 2026-11-13 复核：`ref_price` 已随每笔成交落库并供 TCA 拆延迟/滑点/冲击；`strategy` 目前只存在于票据与 `book.state["strategy_of"]`，内核域对象不认（内核只有 `sleeve` 一个通道），所以"真 alpha 通道"在数据模型上仍不存在；`effective_bps` 由已存在的 `CostModel.round_trip_bps` 覆盖，不另加方法 |

> 第 7 行是 P26 的**设计**，不是现状——表里其余六项都带 ✅ 和实测数，只有它没有。
> `strategy_id` 与 `effective_bps()` 在当前代码里不存在（`grep -rn "strategy_id\|effective_bps" service/`
> 为空）；要落地得先决定 `strategy` 是进 `Fill` 还是留在票据层，这是产品口径问题，不是补字段。

### 判决语义要扩到六档

```
rejected      证据指向无效应
underpowered  当前样本永远测不出观测效应（需 n 更大），不是"再等等"
testing       效应方向对、样本够、但没过显著性/稳定性门槛
shadow        进影子盘，用真实成交检验
promoted      过全部闸门，可下注
decaying      上线后低于回测分布，降级观察
```

`underpowered` 和 `testing` 必须分开：前者要求"换更大的样本或换更粗的效应"，
后者要求"再多跑一段"。混在一起，模型会一直等一个永远不会来的判决。

### 输出契约（每个研究答案必须自带六项）

`effect` · `ci95 + p(聚类稳健)` · `cost_bps_effective` · `mde + trades_needed` ·
`trials_total + p_adjusted` · `residual_alpha(t)`。

缺任何一项，这条"知识"不成立，和 `06` 里"没有 caveats 的观点不算知识"是同一条规矩。

## 3.1 P20 实测：裁判会说是，且不读未来

`service/research/controls.py` 用注入真值跑**真实的** `runner.run()`，
五种世界各 5 个种子（合成市场 240×260，σ 2.2%，赢家线 5%）。
P21 换成内核费用后同一套实验重跑了一遍，两次结果并排：

| 世界 | P20 真值（20bps） | P20 录取 | P21 真值（85bps） | P21 录取 | P21 中位超额 |
|---|---|---|---|---|---|
| `null` | α=0 | 0/5 | α=0 | 0/5 | −0.834% |
| `placebo` | +0.5%，池子选不中 | 0/5 | +1.0%，池子选不中 | 0/5 | −0.854% |
| `weak` | +0.2% | 0/5 | +0.5% | 0/5 | −0.315% |
| `mid` | +0.5% | **5/5** | +1.2% | **0/5** | +0.336% |
| `strong` | +1.0% | 5/5 | +2.0% | **5/5** | +1.123% |

两次实验各自通过：null/placebo 零录取，随机录取对照被显著击败
（lift 从 +60% 升到 **+80%**，因为分母更诚实）。差别在阈值：

- P20 的放行点是 **0.2%/笔**，正好等于当时的 1× 成本；
- P21 的放行点是 **1.7%/笔**，因为裁判要求候选活过 **2× 成本**（85bps × 2），
  而 +1.2% 的世界虽然净超额 +0.336%、p 显著，仍被 `2x-cost` 拦下。

**边界**：合成世界高斯、同方差、iid，TPR 是**上界**；真实事件票条件波动 4–8%，
功效按 σ⁻² 衰减。校准通过只说明"裁判不是哑的"，不说明"它在真实数据上够灵敏"。
详见 `reports/P20_referee_calibration.md` 与 `reports/P21_cost_unification.md`。

## 3.2 P21 实测：换成本之后，仓位表清空

18 份历史判决按内核成本重跑（7 份是 P5 之前非法 T+0 的 spec，被解析器正确拒绝）：

- **3 个 `testing → rejected`**，全是转债结构；
- 唯一候选（正股跌停 → 买转债）从 **+0.298% → +0.098%**，p 0.078 → 0.339；
- 重判后 **0 个 testing、0 个 promoted**。

`¥5,000 / 3 只持仓` 的两个数：**盈亏平衡 0.85%/笔，裁判放行 1.7%/笔**。
九个结构里最好的毛边是 +0.30%——离盈亏平衡差 3 倍，离放行差 5.7 倍。
这不是调参数能补的差距，是量级问题。

## 3.3 P22 实测：分母第一次是真的

`service/research/registry.py` 把每次 run 写进 `data/research.sqlite`。
分母按**搜索次数**累加（`variants_total`），不按 run 次数：

- 10 个 preset → **124 次搜索**，第一次 run 用 8 deflate，最后一次用 124；
- 重复跑同一个 spec 记为新 `look`，不记为新 trial；
- BH-FDR 在族内算：min p **0.339**，`program_fdr` **1.0**，q=0.10 下 **0 survivors**。

P8 的反事实：最好 p=0.078、9 条假设，BH 第一档门槛 `0.10/9 = 0.0111`——差 7 倍。
那个 `testing` 不是判断错了，是当时没有分母。

同一轮还修掉一个记录缺陷：旧 verdict 文件缺 `link_pool`/`rank_dir`，
重放会变成另一个假设（详见 `P21` §3.1）。**不能复现的记录不进分母。**

## 3.4 P23 实测：残差也不是 alpha

`attribution.py` 用**同日特征近邻**做基准（不估系数，避免在同一批样本上拟合），
特征只用 T 日收盘及之前，近邻用与被判交易相同的 entry/exit 口径：

| preset | 等权超额 | 匹配残差 | t | n |
|---|---|---|---|---|
| broken_board_deepest | −0.96% | −0.91% | **−3.20** | 868 |
| limit_up_all | −0.52% | −0.27% | −1.03 | 2,663 |
| cb_link_down | +0.10% | **+0.13%** | 0.58 | 295 |
| cb_link_down_rich | +0.08% | **+0.13%** | 0.70 | 292 |

匹配让所有结构的残差**都比等权超额高 1–25bps**（等权市场对高 beta/小市值/强反转
更苛刻），但**符号一个没变**：亏的仍亏，唯一略正的仍只有 t≈0.7。
`blocks_promotion()` 要求 `n≥100 且残差>0 且 t≥2`，默认在
`run(attach_attribution=True)` 时生效；k=10/20/40 下残差 0.10–0.13%、t 0.53–0.70，
不是调参产物。详见 `reports/P23_attribution.md`。

## 3.5 P24 实测：不是看不见，是没有

`_trade_stats` 改为按日 block bootstrap；`power.assess()` 给每个判决附 MDE 与所需样本。

| preset | MDE | 门槛（2×成本） | 天数 | 笔/天 |
|---|---|---|---|---|
| limit_up_first | 20bps | 200bps | 917 | 44.5 |
| broken_board_deepest | 70bps | 90bps | 915 | 1.0 |
| cb_link_down | 56bps | 80bps | 302 | 1.0 |
| cb_link_down_rich | 48bps | 80bps | 300 | 1.0 |

**十个结构无一 `underpowered`**：MDE 18–70bps，门槛 80–228bps。它们本来能看见
一个值得交易的东西，看见的是零或负数。唯一候选要把它那 +8bps 测到 80% 把握，
需要 **9,951–12,300 个交易日**（约 40–49 年）——不是样本问题，是效应太小。

判决语义扩到六档后，`underpowered` 只用于"正效应、p>0.10、且 MDE>门槛"；
设计能看见却仍不显著，一律 `rejected`。详见 `reports/P24_power.md`。

## 3.6 P25 实测：装好了，但暂时没东西可看

`decay.py` 三路检测 + 状态机（`insufficient / ok / watch / decaying`）：
SPRT 判定 `edge_gone`，或 CUSUM 与滚动 z **同时**报警，才叫 `decaying`；
单路报警只到 `watch`。基准只接受两种证据（逐笔 `mean/std`，或 `cagr/sharpe` 近似），
没有 sigma 就判 `no_baseline`，不造。

今日真实输出：`llm` 与 `cb_link_down` 为 `no_baseline`，`core_etf` 有基准但 0 天净值
→ `insufficient`。**没有一条被晋升过的策略，这是本轮工作的结果，不是监测器的缺陷。**

SPRT 第一版把似然比写反（边缘完好时判"没了"），被两个方向相反的单元测试抓住。
输出不含 `action/sell/reduce/should`，有测试遍历字符串守住。
详见 `reports/P25_decay.md`。

## 4. 实施顺序与理由

```
P20 校准(controls) ✅ → P21 成本(costs) ✅ → P22 登记/FDR(registry) ✅
→ P23 归因(attribution) ✅ → P24 功效(power) ✅ → P25 衰减(decay) ✅ → P26 候选工厂(factory)
```

**为什么必须先校准**：其余六项都是在优化一台可能坏掉的仪器。先证明它能说"是"，
它说的"不"才有意义。校准也是唯一一项**不依赖历史结论、结果立即可判**的工作。

P26 候选工厂放最后，因为批量生成候选会把 trials 迅速抬高；在登记与 FDR 就位之前
做工厂，等于自己制造数据窥探。

## 5. 真 alpha 从哪来：成本决定搜索空间

现在的搜索空间：事件驱动 + `next_open` + `hold∈{0,1,2}` + 等权超额 + 单一成本。

在 ¥5,000 账户上，票越小成本越高（1 只 45bps，5 只 125bps）。P21 之后这两个数是实测的：
**盈亏平衡 0.85%/笔，裁判放行 1.7%/笔**（3 只持仓）。九个结构全在这个区域，
最好的毛边 +0.30%。

三个方向（按边际信息量排序）：

1. **把持有期从 {0,1,2} 拉到 {5,10,20,60}**。成本不变，预期收益变大，成本占比从
   30–100% 降到 2–10%。唯一活着的核心 ETF 就是这一类——这不是巧合。
2. **横截面打分替代事件池**。全市场每日 rank → 分位组合。候选空间从"9 个池子"
   变成"几千个 (特征, 持有期, 分位)"，FDR 才有用武之地，也才有"真 alpha"的
   统计容量。
3. **regime 条件化**。同一结构在不同宽度/波动/涨停家数下符号可能相反；现在是把
   regime 当噪声平均掉了。`analog.regime_table` 已有，但没接进 `run()` 的分层。

一句话：**不是市场没有 alpha，是搜索空间全落在成本否决区。**

## 6. 负面清单

- 裁判未校准前，不要再测第 10 个短线结构（信息量为零，且抬高 trials）。
- 不要为了让候选过关放宽 DSR 0.95 / PBO 0.30。
- 不要先补分钟数据（那是执行精度，不是信息量）；先修 p 值口径与成本。
- 不要用"影子盘跑 100 笔"替代校准（100 笔的 power 接近 0）。
- 不要让内核产生方向（这条已经做对了，保持）。

## 7. 90 天验收（只看数字）

| 指标 | 目标 | 检查方式 |
|---|---|---|
| TPR（注入 α=+0.5%） | ≥ 80% | ✅ 100%（5/5，合成世界） |
| FDR（注入 α=0） | ≤ 5% | ✅ 0%（0/5）；placebo 0/5 |
| gate vs 随机录取 | 显著更优（p<0.05） | ✅ TPR 100% vs 随机 40%，lift +60% |
| 研究/执行费用差 | < ¥0.01/笔 | ✅ 同一 `CostModel`，6 个用例锁住 |
| 历史 9 条假设重跑 | 至少 1 条 verdict 变化 | ✅ 3 条 `testing → rejected`，0 个 testing 残留 |
| `trials_total` | 由"单次 grid"改为"程序累计" | ✅ 10 runs = 124 searches，DSR 分母随之上升 |
| 每个 testing 判决 | 附带 `mde` 与 `trades_needed` | ✅ `payload.power` 恒在；`underpowered` 有独立判决与测试 |
| 新增假设进入 shadow | ≥ 1 条 | 若 0 条且校准通过 → 接受"该规模无可交易 alpha"，关进攻仓 |

## 8. 结论

内核的下一步不是更多功能，是**刻度**。

先让它能被证明会说"是"，它说的"不"才有意义；先让成本与计数诚实，`testing`
才不会变成一个永远等不到的判决；先把成交与归因字段补齐，"真 alpha"才有一个可以
被测量的定义。

在此之前，这个系统提供的是**单向的否定**——有价值，但只是半台仪器。
