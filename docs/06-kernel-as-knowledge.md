# 内核即信息源：三层契约

一句话：**内核不是顾问，是仪表盘。**

> **术语范围**：本文的"内核"指**执行层**（`decisions.py` + `guard.py` + `service/kernel/`），
> 不是某一个包。`service/kernel/` 自身只是语义库：不取数、不落盘、不出票、不判断方向，
> 也不执行风控——`kernel/risk.py` 与 `kernel/engine.py` 是 `tests/golden/` 的参考实现，
> 生产代码被禁止导入它们（`tests/kernel/test_boundaries.py`）。所以下面说"内核不可以说
> '所以卖'"时，约束的是整个执行层；单看 `service/kernel/`，它连"卖不卖"这个问题都收不到，
> 只收到一个已经成形的 `Intent`。

仪表盘不会说"该左转了"。它说：时速 62、前方 40 米有弯、路面摩擦系数 0.4、按当前速度刹停需要 38 米。
剩下的事交给开车的人。

这条界线在 P14 时我画错过一次：当时做了一层 `advice`（止损建议 / 再平衡建议 / 额度建议），
自以为是"只提建议、不执行"，其实"建议"里已经含了行动指令（`action: SELL_ALL`）。
P15 把它整个删掉，换成**只有事实、历史分布和条件测算**的观察层。

---

## 1. 三层，不是一个四层

| 层 | 它回答什么 | 产出 | **禁止** | 代码 |
|---|---|---|---|---|
| **事实** | 现在是什么样 | 行情、持仓、账本、约束状态 | 推断、打分 | `adapters/`、`market.py`、`book.py` |
| **信息** | 类似情况之后发生过什么；如果你这么做要付多少 | 条件分布、区间、成本、容量、暴露 | **任何行动指令**（买/卖/减/加/该） | `analog.py`、`knowledge.py`、`observation.py` |
| **执行** | 怎么合法地把钱花出去 | 手数、限价、止损、T+1、涨跌停、风控、成交 | 判断方向 | `decisions.py`、`guard.py`、`kernel/` |

界线的一句话版本：

> 内核可以说「收盘 9.24，止损 8.90，已连续 3 日在止损下；次日开盘退出要付 ¥5 手续费 + 1.2bps 冲击，
> 净得 ¥918.4；这只票过去 250 日单日跌幅 ≤ -3% 出现过 14 次，次日开盘买入持 5 日的中位数 -1.2%、胜率 36%、最差 -9.4%」。
>
> 内核不可以说「所以卖」。

## 2. 观察对象长什么样

```jsonc
{
  "id": "stop:002966.SZ",          // 由事实派生，不是提案编号
  "kind": "stop_breach",           // stop_breach | single_name_cap | industry_cap | target_drift
  "subject": "002966.SZ",
  "attention": "high",             // 这个事实背后压着多少账户风险
  "fact": {
    "close": "9.24", "stop": "8.90", "breach_pct": -0.038,
    "sessions_below": 3, "ticket_id": "td-20261020-ab12cd34"
  },
  "measures": {
    "exit_at_next_open": {         // 明确假设："如果"在次日开盘退出
      "qty": 100, "qty_sellable_today": 0, "blocked_t1": true,
      "fee_cny": 5.0, "impact_bps": 1.2, "impact_cny": 0.11,
      "net_if_filled_at_ref": 918.4, "fill_basis": "next_open"
    },
    "history": {                    // 这只票自己的历史，不是全市场
      "condition": "单日跌幅 <= -3%", "horizon": 5, "entry": "next_open",
      "n": 14, "median": -0.012, "win_rate": 0.36, "worst": -0.094
    }
  },
  "constraints": ["T+1: 今日可卖 0 / 持仓 100（买入当日不可卖）"]
}
```

没有 `action`，没有 `recommendation`，没有 `should`。测试 `test_observation_has_no_action_field`
会遍历返回的每一个 dict key，出现这些字段直接失败——这条约束是**被测试守住的**，不是靠自觉。

三类观察：

| kind | 事实是什么 | 测算是什么 |
|---|---|---|
| `stop_breach` | 收盘价与票据止损的关系、连续几天在下方 | 次日开盘退出要付多少；这只票历史上类似下跌后怎么走 |
| `single_name_cap` / `industry_cap` | 权重与上限的关系 | 要降到上限需要卖出多少金额 |
| `target_drift` | 注册规则的**目标**权重与账本**实际**权重的差 | 补齐差距的订单清单、费用、换手、交易后权重 |

`target_drift` 有一个刻意的处理：整手买不起的 sleeve（例如 ¥5,000 账户买不起 511010 的一手）
**不算偏离**。规则在这个账户规模上不可执行，不是被违反。把"买不起"混进"漂移"会让模型去追一个
它永远追不到的数字。

## 3. 唯一的硬约束不是建议

有持仓收盘价低于它自己的止损时，新开仓返回 409 `OPEN_VIOLATION`。这不是建议，理由是：

1. 判断依据是**价格**，不是"模型有没有回应某条消息"——没有消息可回应；
2. 规则内容是"风险预算已违约就不加仓"，和"单票不超 30%"是同一类约束；
3. **卖出永远不受限**。

所以系统里没有任何"待处理建议"表，也没有 accept/reject/defer。模型做没做，看 `orders` 和 `cases`，
那才是真正需要被审计的记录。

## 4. 信息源的覆盖面

`GET /knowledge/cards` 按四个层次列出全部可问的问题：

| 层 | topic | 回答什么 |
|---|---|---|
| 市场 | `regime` | 四种状态各自的历史前瞻收益（含重叠样本的警告） |
| 市场 | `/discover` | 宽度、涨停结构、行业分化、跳空行为 |
| 标的 | `analog` | 最像的 k 次历史片段，之后 1/2/3/4/5/10 日分布 |
| 标的 | `distribution` | 尾部、偏度、峰度、最大回撤、最长连跌、自相关 |
| 标的 | `crowding` | 换手分位、离 250 日新高、量比、连涨天数 |
| 标的 | `liquidity` | 1000/5000/20000 股的参与率、冲击 bps、1% ADV 容量、涨跌停距离 |
| 组合 | `risk` | 历史模拟 VaR95、最差单日、集中度、持仓相关性、距减半线的金额 |
| 组合 | `position` | 单笔的止损距离、行业暴露、风险金额 |
| 历史结论 | `ledger` | 九个已证伪的结构，以及证伪它们的数字 |

每条都带 `caveats` 和 `provenance`。没有这两样的"知识"在本系统里不算知识，只算观点。

### 为什么这些数字值得信

以 `analog` 为例（105 万行索引，920 个交易日）：

1. 特征只用 **T 日收盘及之前**；
2. 个股六维按**当日横截面** z-score，市场二维按**时序** z-score（否则同日全市场同值，标准化是 0/0）；
3. 前瞻收益按**次日开盘买入**计算，与 `fill_mode=next_open` 一致；
4. 排除与查询日**重叠的窗口**（`|Δday| < 最长持有期+1`），否则"预测"会用到自己的未来；
5. 置信区间以**交易日**为重采样单位做 block bootstrap——同一天的 6 个样本不是 6 个证据；
6. 最近邻距离用 100 个随机标的的分布校准，输出 `nearest_percentile`。距离 0.28 听起来很近，
   但如果 90% 的随机标的都在 0.3 以内，它就毫无信息量。

冷启动 14 秒，落盘缓存后 0.2 秒。`scripts/prepare_session.py` 在模型开会前热好。

## 5. 为什么"信息"比"建议"更能减少幻觉

模型编造交易理由，通常不是因为想骗人，而是因为**没有可核对的东西**。信息源把可核对的东西塞到它手边：

1. **价格不能编**：`propose` 的 schema 里没有 `qty` / `price`，多传一个字段就是 422；
2. **历史不能编**：`analog` 给出日期、标的、距离，模型可以自己 `quant_bars` 核对；
3. **显著性不能编**：`ci95` 跨零就是跨零，`n_days` 小就是小；
4. **成本不能编**：`liquidity` 给出参与率和 bps，`observation` 给出退出净得；
5. **失败不能编**：`ledger` 里有 9 个被数字杀过的结构；
6. **责任不能转移**：建议层没了，就没有"是它让我卖的"这种说法。决策日志里的 `actor` 只有 `agent` 或 `human`。

第 6 条是这次改动的真正理由：**建议层提供了一个甩锅的接口。**
一条 `action: SELL_ALL` 会让"我为什么卖"这个问题有一个现成的、不需要负责的答案。
删掉它，模型每次都得自己写 thesis。

## 6. 还没做到的

1. **`regime` 两套口径**：`analog.regime_table` 用流动性池复算，`/regime` 用全市场。
2. **`analog` 没有文本维度**：新闻、公告、研报不进特征。
3. **ETF 没有类比索引**：只读 `daily`，ETF 在 `fund_daily`。
4. **分钟级只覆盖持仓**，全市场盘中止损做不了。
5. **`risk` 的历史模拟只有 60 日**：没经历过的事件不在分布里。

前四条写在 `reports/P15_kernel_as_information.md` 里，和代码一起版本化。
